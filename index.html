01 — 问题

程序员经常问：这段代码为什么这么写？

现有工具各自回答了一小截，却没有把答案串成一条可查询的链路。

git blame

只告诉你是谁改的，不告诉你为什么改、被什么约束。

GitHub 搜索

只能搜文本。PR 讨论过几年就沉了，检索成本极高。

ADR 工具

要求人手工写。写完和代码脱节，维护成本高、覆盖不全。

AI 编程助手

通常只看当前文件，不懂历史约束和被否决的方案。

02 — 方案

三层信息，一张图

用 tree-sitter 把代码解析成 AST 与关系边，存入 Dgraph； 叠加 Git 时间轴与 PR / Issue / ADR 中的决策信息。 支持查询任意历史时刻的代码图，也支持查某一行代码背后的决策来源。

输入 源码仓库 Python / TypeScript
输入 Git 历史 commit · blame · diff
输入 决策源 PR · Issue · ADR
解析 tree-sitter AST · uses · defined_by
抽取 Decision Extractor 原因 · 备选 · 状态
存储 Dgraph CodeNode · Decision · Discussion
出口 CLI · Web · AI Context why / graph / export
01

历史时刻可查询

codegraph graph --at 2024-06-01 取回那一刻的结构快照，而不是今天的 HEAD。

02

一行代码 → 决策来源

codegraph why file:line 直接吐出决策卡片：原因、备选、讨论、是否已被取代。

03

矛盾决策可检测

codegraph conflicts 扫描相互冲突的 accepted 决策，避免规则打架。

03 — 演示

终端里的一次「为什么」

04 — 命令契约

七个核心命令

接口稳定优先。所有命令支持 --help，输出中文说明。

codegraph index <path>

解析代码 + 摄取 Git 历史 + 写入 Dgraph

--since · --lang
codegraph why <file>:<line>

返回该行的决策来源卡片

决策核心
codegraph graph --at <date>

返回指定时刻的代码图（JSON）

--scope
codegraph decisions --file <path>

返回决策演化链

--timeline
codegraph conflicts --scope <path>

检测相互矛盾的决策

状态冲突
codegraph export --for-ai

导出 AI Agent 可用的上下文包

--scope
codegraph serve

启动本地 Web 可视化服务

Cytoscape.js

05 — 图模型

三类实体，关系即答案

Schema 是核心契约，改动需评估迁移成本后再确认。

CodeNode 结构
  • kind function / class / …
  • file_path 源码位置
  • valid_from/to 有效期
  • uses 引用关系
  • decided_by → Decision
Decision 决策
  • content 做了什么决定
  • reason 为什么
  • alternatives 否决了什么
  • status accepted / superseded
  • justifies → CodeNode
Discussion 讨论
  • platform github / gitlab
  • title 主题
  • url 深链
  • participants 参与者
  • created_at 时间

和现有工具的关系

现有工具通常是「三选一」

  • 静态代码图 Joern · CodeQL
  • 决策记录 ADR 工具
  • Git 时间旅行 code-nexus
→

CodeGraph 原生整合

  • 结构 + 决策 + 时间轴
  • 同一图上的多跳关联查询
  • CLI / Web / AI 一致接口
